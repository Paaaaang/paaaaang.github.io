# 봇 차단 — 무엇이 되고 무엇이 안 되는지

작성일: 2026-09-20

## 먼저, 잘못 알기 쉬운 것

> "링크를 공유하지 않으면 다른 사람은 못 본다"

**사실이 아닙니다.** GitHub Pages 무료 플랜은 **공개 레포에서만** 동작합니다. 즉:

- 주소 `https://paaaaang.github.io/` 는 누구나 추측할 수 있습니다
- `github.com/Paaaaang` 에 들어가면 레포 목록이 그대로 보입니다
- 레포 소스도 전부 공개됩니다 (`src/content/profile.ts` 포함)
- TLS 인증서 투명성(Certificate Transparency) 로그에 호스트명이 기록됩니다
- GitHub Pages 도메인 전수 목록을 수집해 공개하는 서비스가 여럿 있습니다

그래서 **여기 올린 것은 공개된 것으로 취급해야 합니다.**
휴대폰 번호와 상세 주소를 넣지 않기로 한 결정은 이 사실에 근거합니다.

## 지금 적용된 것

### 1. `public/robots.txt`

일반 검색엔진(Googlebot, Bingbot, Yeti, Daumoa 등)과
AI 학습·수집 크롤러를 명시적으로 차단합니다.

차단 목록에 넣은 AI 크롤러:
`GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-Web`,
`anthropic-ai`, `CCBot`, `Google-Extended`, `PerplexityBot`,
`Applebot-Extended`, `Bytespider`, `Amazonbot`, `Meta-ExternalAgent`,
`cohere-ai`, `Diffbot`, `Omgilibot`, `ImagesiftBot`, 그리고 `*`.

### 2. `index.html` 의 robots 메타 태그

```html
<meta name="robots" content="noindex, nofollow, noarchive, nosnippet, noimageindex" />
```

robots.txt 만 걸면 **이미 색인된 페이지는 빠지지 않습니다.**
크롤러가 robots.txt 때문에 페이지를 못 읽으면 noindex 도 못 읽기 때문입니다.
둘을 함께 걸어야 합니다.

### 3. 이메일 난독화

이메일을 HTML 에 그대로 쓰지 않고 `['play0414', 'naver.com']` 조각으로 보관했다가
브라우저에서 합칩니다. 정적 HTML 만 긁는 수집 봇에는 잡히지 않습니다.

## 이것으로 막히는 것과 안 막히는 것

| | 막히나 |
|---|---|
| 구글·네이버 검색 결과 노출 | 막힘 |
| ChatGPT·Claude·Perplexity 등의 학습·수집 | 규칙을 지키는 한 막힘 |
| 단순 이메일 수집 봇 | 대체로 막힘 |
| **robots.txt 를 무시하는 악성 스크래퍼** | **안 막힘** |
| **주소를 아는 사람이 직접 접속** | **안 막힘** |
| **레포 소스 열람** | **안 막힘** |

`robots.txt` 는 **요청이지 통제가 아닙니다.** 법적 구속력도 없습니다.
GitHub Pages 는 HTTP 응답 헤더를 설정할 수 없어서
`X-Robots-Tag` 같은 강한 수단도 쓸 수 없습니다.

## 진짜로 막아야 한다면 — Cloudflare Pages + Access

인증을 통과한 사람만 볼 수 있게 하는 유일한 방법입니다. 무료 플랜으로 가능합니다.

1. **레포를 비공개로 전환**
   Settings → General → Danger Zone → Change visibility → Private

2. **Cloudflare Pages 에 연결**
   dash.cloudflare.com → Workers & Pages → Create → Pages →
   Connect to Git → 이 레포 선택

3. **빌드 설정**
   | 항목 | 값 |
   |---|---|
   | Framework preset | Vite |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | 환경 변수 | `VITE_BASE` = `/` |

4. **Cloudflare Access 걸기**
   Zero Trust → Access → Applications → Add an application → Self-hosted →
   도메인에 Pages 주소 입력 → Policy 추가

   정책 예시:
   - **Allow / Emails** — 채용 담당자 이메일을 직접 등록
   - **Allow / One-time PIN** — 아무 이메일이나 입력하면 PIN 을 메일로 받아 입장

5. **GitHub Actions 배포 워크플로 삭제**
   `.github/workflows/deploy.yml` 은 더 이상 쓰지 않습니다.

### 이 방식의 대가

채용 담당자가 링크를 열면 **인증 단계를 한 번 거칩니다.**
One-time PIN 이면 이메일을 입력하고 메일함에서 숫자를 확인해야 합니다.
포트폴리오는 "클릭하면 바로 보이는 것"이 강점이라, 이 마찰은 실제로 이탈을 만듭니다.

그래서 지금은 **민감 정보를 애초에 올리지 않는 쪽**을 택했습니다.
공개해도 괜찮은 것만 올렸으니 인증이 필요 없습니다.
전화번호나 주소를 꼭 넣어야 할 일이 생기면 그때 이 문서대로 옮기면 됩니다.

## 확인 방법

```bash
curl https://paaaaang.github.io/robots.txt
curl -s https://paaaaang.github.io/ | grep noindex
```

Google Search Console 에 사이트를 등록해 두면
색인 상태를 직접 확인하고 제거 요청도 할 수 있습니다.
