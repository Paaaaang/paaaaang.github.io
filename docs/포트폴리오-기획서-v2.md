## 0. 이 문서의 전제

- **노션 PORTFOLIO 페이지는 아직 읽지 못했습니다.** MCP 연동은 404(해당 페이지가 연동 워크스페이스에 공유되지 않음), 공개 링크 `pang9.notion.site`는 작업 환경 네트워크 정책에서 차단됩니다. 그래서 경험 섹션은 **이력서 기준으로 뼈대를 잡고, 노션을 읽으면 채우는 구조**로 설계했습니다. 노션 없이 확정할 수 있는 부분(목표·포지셔닝·IA·템플릿·추출 규칙·디자인)은 전부 확정안입니다.
- 레퍼런스 원문(브런치·코드스테이츠·프라임커리어 등)도 같은 이유로 본문 열람은 막혀 있어, **검색 결과 요약에서 확인된 내용만** 근거로 썼습니다. 출처는 문서 끝에 있습니다.

## C. 포지셔닝 — 정체성을 하나로 모은다

### 문제
노션에는 기획과 개발이 섞여 있어, 그대로 옮기면 "개발도 하는 기획자"인지 "기획도 하는 개발자"인지 흐려집니다. 포트폴리오는 **서비스 기획자 하나**로 수렴해야 합니다.

### 한 줄 (확정)
> **가치와 효율을 찾아내는 서비스 기획자 오평일입니다.**

이력서 맨 윗줄과 같습니다. 서류와 포트폴리오의 첫인상이 일치합니다.

### 이 한 줄을 증명하는 세 기둥

| 기둥 | 뜻 | 증명하는 경험 |
|---|---|---|
| **문제를 다시 정의한다** | 요청받은 말 아래의 진짜 병목을 찾는다 | 면접 운영 시스템 |
| **운영을 구조로 바꾼다** | 한 사람에게 묶인 일을 여럿이 쓰는 구조로 만든다 | 체험관 운영 · 동아리 총무 |
| **기술을 아는 기획을 한다** | 기술의 한계를 문제로 정의하고, 기획안을 직접 검증한다 | 엣지 AI |

### 개발 경험의 자리
- 주인공이 아닙니다. **"기획안을 직접 프로토타입으로 검증할 수 있다"**는 차별점으로만 등장합니다.
- 트러블슈팅은 원칙적으로 뺍니다. 단, **기술 제약이 기획 결정을 바꾼 사례**만 기획 언어로 바꿔 남깁니다 (D 참고).

## D. 노션 → 포트폴리오 추출 규칙 ★

노션을 읽을 때 이 표로 한 줄씩 판정합니다.

| 판정 | 대상 | 예시 |
|---|---|---|
| **남긴다** | 문제 정의 · 사용자/이해관계자 · 요구사항 · 정책/권한 설계 · 화면 흐름/IA · 우선순위와 근거 · 지표 · 회고 | "평가자끼리 서로 못 보게 한다"는 권한 정책 |
| **바꿔 쓴다** | 트러블슈팅 중 **제약 → 기획 결정 변경**으로 이어진 것 | "모델 오탐률이 높았다" → *제약*: 단일 영상 탐지는 오탐이 잦다 / *선택지*: 모델 개선 vs 보조 지표 / *결정*: 멀티센서를 보조 지표로 / *대가*: 하드웨어 비용 증가 |
| **버린다** | 코드 · 라이브러리 버전 · 배포 에러 · 쿼리 최적화 · 기술 스택 나열 | "CORS 에러 해결", "N+1 쿼리 개선" |

**판별 질문 3개** — 셋 중 둘 이상이 "예"면 남깁니다.
1. 이 결정을 개발자가 아니라 **기획자 입장에서** 내렸는가?
2. 결과적으로 **사용자나 운영자의 경험**이 바뀌었는가?
3. 면접관이 **"왜 그렇게 했어요?"** 하고 물을 거리가 되는가?

**용어 치환**

| 개발 언어 | 기획 언어 |
|---|---|
| 구현했다 | 설계하고 직접 만들어 검증했다 |
| API 연동 | 외부 데이터가 들어오는 흐름을 설계 |
| DB 스키마 설계 | 누가 무엇을 볼 수 있는지 정의 (권한·데이터 정책) |
| 버그 수정 | (삭제) 또는 "정책 결함을 발견해 기획을 고쳤다" |
| 성능 개선 | (삭제) 또는 "대기 시간이 사용 흐름을 끊는 지점을 찾았다" |

## F. 경험 케이스 템플릿 (모든 대표 경험 동일)

```
[헤더]
 제목      무엇을 바꿨는지가 드러나는 한 문장
 요약      두 문장
 메타      기간 · 소속 · 팀 구성 · 내 역할(동사로: 직접/참여/조율)

① 문제 정의    요청받은 것 vs 실제 문제
② 목표와 가설  성공을 무엇으로 판단했나
③ 핵심 결정    2~3개. 각각 [선택지 / 결정 / 이유 / 포기한 것]
               + 산출물 1장 (플로우 · IA · 권한표 · 화면설계 중 택1)
④ 검증         어떻게 확인했나 (직접 만든 프로토타입은 여기서 등장)
⑤ 결과와 회고  지표 + "다시 한다면"
   (선택) 기술 제약이 바꾼 결정 — 박스 1개
```

분량: 케이스당 **본문 700~1,000자 + 이미지 2~3장**. 3분 안에 하나를 끝까지 읽는 기준입니다.

## I. 카피와 문체

- 경어체 통일. `im-not-ai` 게이트 통과가 배포 조건 (대구 "A가 아니라 B" 문서당 1회, 연결어미 쉼표 0회 등).

- 담당 범위 동사: **직접 했다 / 참여했다 / 조율했다** 를 섞지 않는다.
- 용어 통일(`ko-style-guide`): 사용자 · 운영진 · 지원자 · 면접관.
