# 2차 개선 계획 — "이 사람이 누구인가"에 먼저 답하기

작성일: 2026-09-20
대상: 1차 구현본(에디토리얼 + 절제된 3D)

---

## 점검 결과 요약

1차 구현본의 첫 화면은 **주장**으로 시작한다.

> 요청의 표면이 아니라 / 그 아래의 운영 실태를 / 먼저 확인합니다

문장 자체는 이 사람의 서사를 정확히 요약한다. 그러나 **누가 하는 말인지를 모른 채 읽게 된다.**
이름 `오평일`은 화면 하단 14px 메타 줄에 있고, 사진은 사이트 전체에 한 장도 없다.

크리에이티브 스튜디오 포트폴리오라면 주장이 먼저 와도 된다. 브랜드가 곧 주장이기 때문이다.
그러나 이 사이트는 **신입 지원자의 채용용 포트폴리오**다. 읽는 사람은 채용 담당자이고,
그가 30초 안에 확인하려는 것은 순서가 정해져 있다.

1. 누구인가 (이름, 얼굴, 상태)
2. 우리 공고에 맞는 사람인가 (직무, 신입/경력, 졸업 시점, 근무지)
3. 무엇을 할 수 있는가 (강점)
4. 근거가 있는가 (성과 숫자)
5. 어떻게 연락하는가

1차 구현본은 4번(증거)과 5번(연락)은 갖췄지만, **1·2·3번이 비어 있거나 흩어져 있다.**

---

## 구체적 문제 7가지

| # | 문제 | 근거 | 영향 |
|---|---|---|---|
| 1 | 얼굴이 없다 | 사이트 전체에 인물 사진 0장 | 사람을 뽑는 자리인데 사람이 안 보인다 |
| 2 | 이름이 묻혀 있다 | `오평일` 이 본문 중 가장 작은 14px 줄에 위치 | 누구 사이트인지 스크롤해야 안다 |
| 3 | 지원 직무가 없다 | 이력서의 `서비스기획 / 사업기획 / 경영기획` 이 사이트에 미반영 | 공고 적합성 판단 불가 |
| 4 | 신입 여부·졸업 시점이 약하다 | `졸업 · 2019.03 – 2026.02` 만 표기, `신입` 단어 없음 | 경력자로 오독될 여지 |
| 5 | 강점 3가지가 흩어져 있다 | 자기소개서 3번 문항의 강점이 케이스 3곳에 분산 | 요약해서 기억할 것이 없다 |
| 6 | 이력서 원본을 받을 수 없다 | PDF 다운로드 경로 없음 | 담당자가 사내 공유를 못 한다 |
| 7 | 연락이 18,000px 아래에만 있다 | Contact 가 최하단 단일 지점 | 중간에 마음먹은 사람이 이탈한다 |

## 개선 작업 (2차)

### A. 히어로 재구성 — 정체성 우선

기존 1단 구성을 2단으로 바꾼다.

```
┌──────────────┬────────────────────────────────┐
│              │ 서비스 기획자 · 신입            │
│  이력서 사진  │ 오평일                          │  ← 이름을 가장 크게
│  (4:5 프레임) │ ─────────────────────           │
│              │ 요청의 표면이 아니라 그 아래의    │  ← 주장은 이름 다음
│              │ 운영 실태를 먼저 확인합니다       │
│              │                                 │
│              │ [신입] [2026.02 졸업] [군필]     │  ← 적합성 판단용 칩
│              │ [서비스기획·사업기획]            │
│              │                                 │
│              │ 이력서 PDF ↓   메일 보내기 →     │
└──────────────┴────────────────────────────────┘
```

- 사진은 `public/media/profile/` 에 넣고 `profile.photo` 경로만 연결한다.
  넣기 전까지는 다른 자료 슬롯과 같은 빈 프레임이 그려진다.
- 모바일에서는 사진이 위, 텍스트가 아래로 쌓인다. 사진은 화면폭의 55%로 제한한다.
- 3D 배경은 히어로에서 한 단계 더 물러난다(현재 0.7 → 0.55). 사진과 경쟁시키지 않는다.

### B. "어떤 사람인가" 요약 섹션 신설

히어로 바로 다음, 증거(숫자) 섹션 앞에 넣는다.
자기소개서 3번 문항의 강점 3가지를 그대로 쓴다. 새로 지어내지 않는다.

1. 한 사람에게 묶여 있던 운영을 여럿이 쓸 수 있는 구조로 바꾸는 실행력
2. 아이디어를 원가와 수익까지 끌고 가는 사업 감각
3. 기술의 한계까지 보고 서비스 흐름에 앉히는 이해도

각 강점 카드에는 **그것을 증명하는 케이스로 가는 링크**를 붙인다.
주장과 근거를 한 화면에서 연결해야 기억에 남는다.

### C. 기본 정보 스트립

칩(chip) 형태로 히어로 안에 배치한다. 이력서에 있는 사실만 쓴다.

`신입` · `2026.02 졸업` · `조선대 컴퓨터공학과 + 경영학부 복수전공` ·
`군필` · `희망 직무: 서비스기획 / 사업기획 / 경영기획` · `희망 근무지: 서울 · 성남 분당 · 광주`

> 휴대폰 번호와 상세 주소는 1차 결정대로 계속 제외한다.
> 군필 여부와 희망 근무지는 국내 채용에서 표준 항목이고 연락처가 아니므로 포함한다.

### D. 스크롤 헤더에 정체성 유지

현재 좁은 화면 상단 바에 이름만 있다. 여기에 **직무와 메일 버튼**을 더한다.
넓은 화면에서도 스크롤을 내리면 같은 바가 나타나게 한다.
18,000px 문서 어디에서 마음먹어도 한 번에 연락할 수 있어야 한다.

### E. 이력서 PDF 다운로드

`public/오평일_이력서.pdf` 자리를 만들고 히어로와 Contact 두 곳에 버튼을 둔다.
파일이 없으면 버튼은 렌더하지 않는다(깨진 링크를 만들지 않는다).

### F. 메타데이터 보강

`og:image` 를 프로필 사진으로 연결한다. 링크를 공유했을 때도 얼굴이 먼저 보이게 한다.

## 작업 순서

1. `profile.ts` — `photo`, `identity`, `strengths`, `resumePdf` 추가
2. `Hero.tsx` — 2단 레이아웃으로 재작성
3. `Identity.tsx` — 강점 3가지 섹션 신설
4. `Nav.tsx` — 스크롤 헤더에 직무 + 메일 버튼
5. `SceneCanvas.tsx` — 히어로 구간 3D 존재감 하향
6. `index.html` — og:image
7. 반응형·모션축소·빌드 검증

## 검증 기준

- 1440px / 390px 첫 화면 캡처에서 **스크롤 없이** 얼굴·이름·직무·신입 여부가 모두 보일 것
- 가로 스크롤 없음
- `prefers-reduced-motion` 에서 전체 내용 정적으로 읽힘
- 타입체크·빌드 통과
